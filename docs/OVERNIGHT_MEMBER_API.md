## Watching and My Bids

`GET /api/bidder/events/:eventId/watching` → `{eventId,releaseId,person:{id,name},lotIds:string[],serverNow}`. An unpublished event has null release and an empty collection. VIEW is sufficient; BID is not required. Watches bind actor/event/immutable release/lot.

`POST` on that route accepts `{actorId,requestId,lotId,watching:boolean}` → `{watch:{eventId,releaseId,lotId,watching,updatedAt},operation:{requestId},replayed,serverNow}`. Unknown keys or malformed UUID/boolean are rejected; an actor change is `409 ACTOR_CHANGED`. Desired state and the owned request record commit atomically. Same actor/key + same payload returns the original operation; changed payload/event is `409 IDEMPOTENCY_CONFLICT`. Foreign/unpublished lot is 404. `GET /watching/requests/:requestId` recovers only that actor's event operation under current session+VIEW. It can describe an older operation even after a later key removes the watch; refresh the collection for current desired state.

`GET /api/bidder/events/:eventId/my-bids` → `{eventId,releaseId,person:{id,name},currency,rulesetId,scale:100,phase,serverNow,bids:[{receipt,lot:{id,number,title},standing:{currentAmountMinor,leadingBusiness,acceptedBidCount,version,updatedAt},recordedState}]}`. History includes the current actor's durable accepted/rejected receipts for this immutable event release, never coworker receipts. Lot projection comes from the published snapshot, never draft content. `recordedState` is leading/outbid/rejected/closed-leading/closed-outbid; leading describes the receipt's business's current standing, not a personal award. Rejected receipt remains rejected even if that business later leads. No winner, finalization or settlement is represented. History/recovery needs VIEW; losing fresh BID or business spending permission does not erase owned history.

Staff can explicitly configure `amountCapMinor` as a positive safe integer or null and `availability` as null, `{mode:'any-time'}`, or `{mode:'window',opensAt,closesAt}`. An unconfigured enable request rejects409 DONATION_POLICY_PENDING; clear controls with `enabled:false`. Omitted fields preserve stored configuration, and unchanged settings leave updatedAt unchanged. New commitments require enabled+ready+current configured availability. Representation is bounded by Number.MAX_SAFE_INTEGER (9007199254740991); this is exact API numeric precision, not a product cap. `GET /api/bidder/events/:eventId/donation-pledges/context` → `{event:{id,name},organization:{id,name},person:{id,name},enabled,businesses:[{id,name,canPledge}],nonprofits:[{id,name,description,version}],unit:'trade-dollar',scale:100,amountCapMinor:number|null,minimumMinor:1,availability,policyReady,availableNow,serverNow}`. Current session+VIEW required; no catalog release needed. Only active event recipients; no runtime default fictional nonprofit. Default disabled; availability is an explicit per-event choice. After settings and current authority waits, database time supplies serverNow and availableNow (enabled+ready+within configured availability); each business canPledge also requires that availableNow and current BID/active chain. The UI does not infer donation readiness from browser time or auction phase.

`POST /donation-pledges` accepts `{actorId,requestId,businessId,nonprofitId,nonprofitVersion,amountMinor}` → `201 {receipt}` only after durable commit. Receipt: `{id,requestId,eventId,organizationId,actorId,businessId,actorName,businessName,nonprofit:{id,name,description,version},amountMinor,unit:'trade-dollar',scale:100,status:'pending_staff_settlement',recordedAt}`. Names/descriptions/version/amount are immutable recorded snapshots. `GET /donation-pledges/:requestId` returns the same owned event receipt under current session+VIEW. Exact owned POST replay is resolved before current enabled/policy/destination/spending refusals; therefore409 DONATIONS_DISABLED or NONPROFIT_CHANGED on that exact request means no original owned receipt exists. Exact replay/recovery survives disable, nonprofit edits and lost fresh-spending grants; a changed actor is409 ACTOR_CHANGED and same actor/key changed payload is409 IDEMPOTENCY_CONFLICT. New disabled pledges are409 DONATIONS_DISABLED; changed/inactive destination version409 NONPROFIT_CHANGED; configured closed/future availability409 DONATIONS_UNAVAILABLE. Foreign destination404; missing spending authority403; invalid amount400.

Staff `GET /api/admin/events/:id/donations` → `{event:{id,name},enabled,policyReady,minimumMinor:1,amountCapMinor:number|null,availability,nonprofits:[{id,name,description,version,active}],pledges:[receipt],serverNow}`. `PUT {enabled,amountCapMinor?,availability?}` → `{enabled,policyReady,minimumMinor:1,amountCapMinor,availability}` saves desired named fields. Staff uses current same-org grants, never BID.

`POST /donations/nonprofits {requestId,name,description}` → `201 {nonprofit:{id,name,description,version}}`; exact retry returns the same resource's current projection without overwriting edits, changed event/name/description with the same actor/key conflicts. `PUT /donations/nonprofits/:nonprofitId {expectedVersion,name,description,active}` → `{nonprofit:{id,name,description,version,active}}`; stale version409 VERSION_CONFLICT. No delete operation. Recorded receipts never follow edits.

`GET /donations/export` returns an authorized, formula-safe CSV attachment from the same read projection, sorted recordedAt/id. Columns: id,request_id,event_id,actor_name,business_name,nonprofit_id,nonprofit_name,nonprofit_version,amount_minor,amount,unit,scale,status,recorded_at. Amount uses exact integer division/remainder and two decimal digits. Quoting escapes commas/quotes/newlines; cells beginning =,+,-,@,tab,CR receive an apostrophe. No cross-event records or spending credentials.
