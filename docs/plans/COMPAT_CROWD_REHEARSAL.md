# Saturn phone rehearsal — 10–15 people, 20 minutes

Use a **practice event**, clearly named “Saturn phone rehearsal.” Add three items and a test nonprofit. Nothing here charges a payment. Keep the host in Studio → Live with **Devices** visible; put the stage on a projector if available.

Bring a mix of updated and older iPhones, budget Androids and Samsung Internet. Have several people open the invitation inside Gmail, Facebook or another app. Include both Wi-Fi and cellular connections. Record the browser and OS versions of any phone that fails; a changed user-agent string is not a different browser engine.

1. **Join, 3 minutes.** Open the link/QR, enter a name and business label, and browse. Staff watch device count and browser mix. Nobody should see an opaque overlay or get stuck loading.
2. **Bid, 5 minutes.** Everyone opens an item and its bid sheet. Check that the amount and Bid button are visible and tappable, including with the keyboard open. Have two people compete, then check the outbid alert and My bids. Do not interpret an Unconfirmed outcome as a failed bid: use Check status.
3. **Reconnect, 4 minutes.** One person opens the sheet, briefly turns on airplane mode, then reconnects and checks status. Confirm that no second bid is created by checking/retrying the original request.
4. **Donate and return, 3 minutes.** Record a test pledge. Ask staff for a rejoin code and use it on another phone. Confirm the original activity is present. A pledge is not a cash payment.
5. **Simple mode, 3 minutes.** Try “Having trouble? Simple mode” on two phones. Join, bid and view the receipt. It works without JavaScript; refresh is how current bids update.
6. **Close, 2 minutes.** Let one item close, confirm its winner, and check that the guest sees the result. Record the handover instructions, then export the practice results.

If someone is stuck, staff check **Devices → Problems** and give them the simple-mode link from Share or Devices. Record the step, time, phone/browser/OS and whether the link opened inside another app. A screenshot is useful, but omit passwords and rejoin codes. Report whether the button was absent, off screen, covered, or unresponsive.

Success: all 10–15 people complete the journey; no invisible sheets, false acceptance or duplicate bids/pledges; staff see reported failures and can move a guest into simple mode. “No reported problems” means no diagnostic reports arrived—it is not proof that every phone is healthy.

This rehearsal supplies physical-device evidence that automated Chromium/WebKit checks cannot. The requested old-iOS simulator matrix remains a separate check; record any unavailable runtime as untested, never passed.
