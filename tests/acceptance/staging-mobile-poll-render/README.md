# Independent mobile polling evidence

This narrow evidence was authored independently before product implementation.
The frozen schema2 contract binds exact assertion IDs and exact baseline failure
IDs. The external kernel is version 3.1.0; repository AGENTS.md still names 3.0.0.

The harness compiles the actual `EventAccess` and actual `DemoEntryForm` TSX only
in memory using bundled Babel, and mounts the installed production React runtime.
It fulfills the actual catalog iframe, JS, CSS, images and fonts directly from
`VERIFY_ROOT/public`. All API requests are fulfilled with browser-local DTOs on
`https://mobile-render.invalid`; unmatched requests are aborted and fail evidence.
No Next process, listener, database, provider call or live browser profile is used.
WebKit and Chromium run sequentially, one browser at a time, with each owned
context and browser closed. The viewport is 390x844, touch enabled.

Acceptance observes real automatic polling at its existing cadence on welcome,
search and bid-review screens. It stores node references and measures retained
main/image/navigation nodes, advanced authoritative timestamps, search and bid
review input identity, value, focus and selection. It separately counts messages
produced by an actual successful parent refresh. Base is expected to fail all
eight acceptance IDs, not because of missing dependencies or timeouts.

Regression challenges changed catalog content and opening amount, changed
standing/next minimum and permission, offline/reconnect, closed phase and its
thirty-second polling policy, and lost-acknowledgement receipt recovery. API/server
and migration byte hashes are frozen separately because this UI fix may not alter
authority, storage, or demo enrollment. This is a bounded client gate and does
not rerun the earlier database-backed synthetic auction contracts.

Adversarial cases delay an old standing response across a permission-generation
change, delay an old parent catalog/context pair across a newer actor response,
delay an old response pair across logout, deny current catalog access with 401,
and fail catalog refresh with 503 while requiring retained stale content and
disabled bidding. POSTs occur only to intercepted `.invalid` endpoints for the
lost transport and logout cases; no network mutation can escape the route handler.

The terminal result uses the kernel protocol with every declared assertion row.
Setup/dependency/bootstrap/unknown runtime failures exit 99 and produce no fake
ordinary RED. Failed behavioral assertions exit 1, successful assertions exit 0.
For standalone debugging the same rows are printed to stdout; normal verification
writes only the kernel-provided result path outside the source snapshot.

Not proven here: exact visual flashing on the user's physical phone, OS keyboard
behavior, real authenticated transport, live database truth, or deployed build
identity. Those remain separate hosted/physical-device evidence and release checks.
